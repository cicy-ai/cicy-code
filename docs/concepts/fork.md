# Fork 分身

**Fork** 是「带着完整上下文,再开一路」。当一个 agent 的会话里已经积累了很多上下文(任务、决定、当前进展),你想在这个基础上再分出一个 agent 继续 —— 就 fork。

```bash
cicy-agent fork <agent>
```

## fork 继承什么

| 项 | 是否继承 |
| --- | --- |
| **对话上下文** | ✅ 源 agent 的完整历史,作为分身的「继承提示词」 |
| **角色模板** | ✅ 同角色 |
| **项目模板** | ✅ 同项目 |
| 网关 / provider / 模型 | ✅ 与源一致(gateway agent) |
| 代理 / MITM / 回复语言 | ✅ |

fork 的 `CLAUDE.md` **不是复制源文件**,而是用当前模板**现场组装**(global + 继承的项目 + 角色);源的**对话**单独通过 `agent-summary` 生成后作为分身的**继承提示词**交给它。两者分开:模板组装的是静态 guidance,历史对话是继承上下文。

## 交接语义

分身被明确告知:「你是源 agent 的**延续**,不是新助手。把继承内容当作自己的记忆吸收,**不要**总结回来、**不要**向任何人汇报交接、**不要**自行继续工作 —— 吸收完回一行确认,然后等用户指示。」中/EN 提示词可在 fork 确认弹窗里切换。

## 什么时候用 fork vs 新建

- **fork**:要延续现有上下文(同一任务的分支、"接着做")。
- **新建 agent**:全新任务/项目,不需要旧上下文 —— 直接用角色 + 项目模板建。
