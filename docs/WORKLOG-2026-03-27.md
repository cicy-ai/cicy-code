## 5. skill 边界重构：`cicy-code` vs `cicy-master`

最终方向明确：

### `cicy-code`
职责：
- 作为 **节点 API 客户端** 使用
- 读取本地 node registry 选择目标节点
- 调用目标节点的 `/api/*`、`/ttyd/*`、`/code/*`

不再负责：
- 节点注册表管理

### `cicy-master`
职责：
- 作为 **节点注册表管理器**
- source of truth = 本地 `~/Private/cicy-node.json`
- 首批命令：
  - `list`
  - `register`
  - `sync`
  - `ping`
  - `health`

架构原则：
- 节点不主动访问 master
- 不要求 `CICY_MASTER_URL` / `CICY_MASTER_TOKEN`
- `CICY_API_TOKEN` 改定义为：**每 node 一个长期 token，由 master / tooling 创建并下发**
- master/工具通过探针管理节点状态，而不是 node 主动自注册
